context: |-
  Heute kennt jaira genau einen Katalog, fest im Code (core/market/market.go). Die einzige Umstellung ist die Umgebungsvariable JAIRA_MARKET_API, gedacht fuer Tests.
  Eine Firma kann damit weder einen eigenen Katalog anbieten noch den oeffentlichen sperren, und ohne Netz geht nichts.
  So loesen es andere: Claude Code hat extraKnownMarketplaces (zusaetzlich) und strictKnownMarketplaces (nur diese) in verwalteten Einstellungen; VS Code hat extensions.allowed und einen privaten Marktplatz; Homebrew hat Taps mit <quelle>/<name>.
  Loesung, so klein wie moeglich:
  - Datei .jaira/market im Repo (wandert mit git zu jedem im Team) und ~/.jaira/market fuer den Rechner. Zeilenformat, von Hand schreibbar: 'source <name> <adresse>' und optional 'only'.
  - Adresse ist eine https-Basis oder ein lokaler Pfad. Ein Spiegel ist eine Kopie des Katalog-Repos samt index.json auf einem internen Webserver, einer internen Pages-Seite oder einem Laufwerk.
  - 'only' in einer der beiden Dateien: der eingebaute oeffentliche Katalog wird nicht gefragt. Die Repo-Datei kann 'only' setzen, die Rechner-Datei kann es nicht aufheben.
  - Bei mehreren Quellen zeigt die Liste eine Spalte Quelle; eine id, die zwei Quellen tragen, verlangt <quelle>/<id> (Exit 3, beide Formen genannt - wie bei Milestones mit gleichem Namen).
  - 'jaira market sources' zeigt, welche Kataloge gelten und woher die Einstellung kommt.
  Die Erlaubnisliste ist der Spiegel selbst: was die Firma nicht hineinkopiert, gibt es nicht. Eine zweite Liste je Eintrag wird nicht gebaut.
  Nicht gebaut: Signaturen. sha256 im Index plus https plus ein Spiegel unter eigener Kontrolle decken den Fall ab.
