# Agent roles and pull-request policy
_Owner: Sascha · EARS · each line one requirement · [tickets] hold the detail_

## Shipping the roles
ROLE-01  The jaira binary shall embed every role of core/role/builtin as a directory whose name is the command the harness invokes. [C9V7ZV, PMF635]
ROLE-02  When `jaira roles install --project|--global|--into <dir>` runs, jaira shall write each role with every file beside its SKILL.md, plus <skills>/jaira/SKILL.md. [C9V7ZV, 7KX89C]
ROLE-03  If an installed file differs from the embedded one and from every shipped version, then jaira shall leave it, report it and exit 3. [C9V7ZV]
ROLE-04  Where `--force` is given, `jaira roles install` shall overwrite an edited file and report it overwritten. [C9V7ZV]
ROLE-05  When an installed file equals a version an earlier jaira shipped, jaira shall replace it without --force and report it updated. [0K8Y6S, PWAF22]
ROLE-06  The installer shall give `.sh` files mode 0755 and restore a lost execute bit on a file it leaves unchanged. [7KX89C]
ROLE-07  Where `--agent copilot` is given, jaira shall install into .github/skills (project) or ~/.copilot/skills (global). [E75R4Q]
ROLE-08  If the roles already sit in another directory the agent reads, then jaira shall write nothing and print the command that updates them there. [E75R4Q]
ROLE-09  Where the agent is claude, `jaira roles install` shall also write the jaira-cockpit mod beside the roles. [NZZDRH, E75R4Q]
ROLE-10  When `jaira update --roles` runs, jaira shall update the roles in every skills directory that already holds them. [PWAF22]
ROLE-11  The `jaira roles list` command shall name the dispatch role, chat model, python command, release owner and PR mode, each with its source. [MG677R, 5A6RJZ, SJ16MC, XB97NJ]

## Who carries a ticket
ROLE-12  While "dispatch" in ~/.jaira/settings.json is not "worker", jaira shall name jaira-dispatcher, one new agent per lane, for a whole ticket. [MG677R]
ROLE-13  Where "dispatch" is "worker", jaira shall name jaira-worker, which works every agentic lane itself and hands only a `context: fresh` lane on. [MG677R]
ROLE-14  The teamlead role shall never edit code and never move a ticket out of a human lane; it delegates every lane. [TWRAP8, 50RA6N]
ROLE-15  When a worker or dispatcher started with --parent has a question, it shall note it on the ticket, SendMessage it to the parent and end its turn. [TECZH5]
ROLE-16  If the parent cannot be reached, then the worker shall note that on the ticket and ask in its own tab, never sending to another peer. [7V1XPB]
ROLE-17  When a question reaches the teamlead, the teamlead shall decide it with a `decision (teamlead <date>)` note where ticket, code or rule settle it, and ask the person only otherwise. [K6PBYR, TWRAP8]
ROLE-18  When one lane has sent work back three times, the worker shall stop and hand the decision to its parent rather than loop again. [K6PBYR, H6CD33]
ROLE-19  The worker and dispatcher shall end their report with one status line `jaira: <ID> <from> -> <to> · branch · commits · gates · notes · verdict`, fixed keys, `-` for empty. [55CS2M, TT3Z11]
ROLE-20  Where something waits for a person, the report shall carry exactly one `needs you:` line above the status line. [55CS2M, TT3Z11]
ROLE-21  Where the board's .jaira/release says teamlead, the worker shall touch no version field, changelog entry or tag. [SJ16MC]
ROLE-22  The worker and dispatcher shall never answer an approval dialog of an agent they started; they report what it asks. [KSGSKK, PEPTWY]
ROLE-23  When the testing lane runs, the worker shall start jaira-role-bughunt as a background subagent and run the tests itself meanwhile. [Z66Z8E, KCRS3W]
ROLE-24  The bughunt role shall verify each finding against the code and note it as `bughunt: change|pre-existing` with a class and an example. [KCRS3W, TW5FE2]
ROLE-25  When a bughunt `change` finding meets the ticket's blocker_rule, the bughunt role shall mark it `bughunt: change: blocker:`. [DF0YD6, R2X4TJ]
ROLE-26  The signoff role shall change nothing and give each ticket one status line, one note table and one recommendation with both move lines. [TWRAP8, GY8T52]
ROLE-27  The acceptance role shall build one page from tickets in a human lane and turn each failed step it reads back into a return or a new bug. [747HER]
ROLE-28  The tester role shall run the suite and report failures without fixing them. [Y2CD9X]
ROLE-29  The tester and logbook-summary roles shall declare `model: haiku`; roles that change code or judge shall declare no model. [Y2CD9X]
ROLE-30  The logbook-summary role shall summarise a period for a project lead as one page without code. [2MJBJM]

## Pull requests and landing
ROLE-31  The jaira-role-pr role shall never merge and never approve a pull request. [A3R6YC, JG3REW]
ROLE-32  When a person invokes /jaira-role-pr, or the cockpit passes --by-person, the role shall open the pull request itself. [A3R6YC, GPFA7B]
ROLE-33  When an agent invokes /jaira-role-pr, the role shall push the branch and hand the create line back unless the base's .jaira/pr says agent. [A3R6YC, JG3REW]
ROLE-34  `jaira roles pr-gate <base>` shall read .jaira/pr, .jaira/pr-when and .jaira/land as <base> holds them, never off the branch's disk. [JG3REW, XB97NJ]
ROLE-35  The pr-gate shall exit 0 only when base's .jaira/pr says agent, a commit in base..HEAD names a ticket, and every named ticket is in its terminal lane or the logbook. [JG3REW]
ROLE-36  Where base's .jaira/pr-when says signoff, the pr-gate shall also accept tickets in signoff or a later lane up to the terminal one. [JG3REW, CRASZS]
ROLE-37  If a named ticket is archived, unknown or unreadable, then the pr-gate shall refuse with exit 3 and name the ticket. [JG3REW]
ROLE-38  Where base's .jaira/pr says none, `pr-gate --land` shall exit 0 only when every ticket is in done and every commit names a ticket. [XB97NJ]
ROLE-39  If base's .jaira/pr says none, then a plain `pr-gate` shall refuse with reason no_pull_requests. [XB97NJ]
ROLE-40  Where base's .jaira/land says agent, `pr-gate --merge` shall exit 0 once every ticket on the branch is in done and every commit names one. [50RA6N]
ROLE-41  When the pr role is about to push, it shall first scan, merge the base, run the full suite, tick suite DoD items, file done tickets, scan again, then push. [AX8K02]
ROLE-42  If pre-push-scan.sh finds a denylist hit, then it shall exit 3 naming commit and file, never the matched text or the pattern. [AX8K02]
ROLE-43  When a commit carries this machine's host name, pre-push-scan.sh shall print a warning and let the push go on. [AX8K02]
ROLE-44  The pr role shall never push with --force or --force-with-lease. [AX8K02]
ROLE-45  Where the remote is GitLab, the pr role shall work through glab; on GitHub, through gh. [WATJDQ, XSGWPX]
ROLE-46  When land.sh runs, it shall merge the base, regenerate the files .jaira/land-regenerate names, push and wait for CI. [50RA6N]
ROLE-47  If `pr-gate --merge` refuses, then land.sh shall merge nothing, print the merge line and exit 3. [50RA6N]
