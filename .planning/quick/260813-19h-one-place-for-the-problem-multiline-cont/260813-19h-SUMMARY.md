# Quick Task 260813-19h: One place for the problem (multi-line context) Summary

Block scalars in ticket frontmatter now read as their content instead of their
header token, jaira writes eligible multi-line values as indented block
literals instead of escaped one-liners, and `context` is the single recorded
reason a ticket exists (`## Description` removed from every place that wrote or
described it).

## What Was Built

**Task 1 — read fix.** `Doc.Scalar` (core/ticket/frontmatter.go) had a case for
`*ast.LiteralNode` added ahead of the generic `GetToken().Value` fallback: a
block scalar's own token is its header (`|`, `>-`, `|-`), not its decoded
content, which lives on `LiteralNode.Value.Value`. `Decode` picks this up for
free since it calls `Scalar` under the hood. Before this fix, a ticket with
`context: |` decoded to `Ticket.Context == "|"`, and the promotion gate (which
only checks non-empty) silently passed it.

**Task 2 — write path.** Three helpers were added next to `encodeScalar`:

- `blockable(v string) bool` — gates whether a value is safe to render as a
  block literal: must contain `\n`, must not end with two-or-more trailing
  newlines (keep-chomping is not supported), no line may have leading or
  trailing whitespace, and it must contain no `\r` or control runes below
  `0x20` other than `\n`. Anything failing any check keeps the existing quoted
  one-liner encoding, which is lossless.
- `renderBlock(key, val, indent, comment string) string` — renders the block
  header (`|` for a value ending in exactly one newline, `|-` for none) plus
  two-space-indented content lines, carrying a trailing comment onto the
  header line.
- `blockExtent(lines []string, start int) int` — finds the last source line an
  entry occupies by scanning forward while a line is blank or more indented
  than the key line, then walking back off trailing blanks. Returns `start`
  unchanged for an ordinary single-line entry.

`NewDoc` (core/ticket/schema.go) now calls `renderBlock` for any
non-raw-literal field where `blockable(v)` is true. `SetScalar`
(core/ticket/frontmatter.go) gained `setScalarWholeEntry`, used whenever either
the new value or the existing node is a block scalar; it mirrors `SetList`'s
whole-entry replacement. A plain single-line-to-single-line edit is completely
untouched — same byte-column splice as before. The old
"not supported by SetScalar" guard was deleted now that the block path handles
that case.

**Task 3 — one place for the problem.** `## Description` was removed from
`newTicketBody` (internal/cli/tickets.go). Five registers now say the same
thing about what makes context usable: the `--context` flag help, the
`create` command's `Long` text, the agent note written into `AGENTS.md`/
`CLAUDE.md` (core/board/announce.go), the pre-process lane prompt
(core/lane/builtin/15-pre-process.md, which now also instructs routing
unusable context to the human lane instead of guessing), and the jaira skill
(`.claude/skills/jaira/SKILL.md`). The sign-off view's follow-up ticket
(internal/tui/signoff.go) had its "why" moved out of a `## Description` body
heading into `context` via a new `followUpContext` helper, joining the
"Raised from the review of..." line, the source ticket's own context/goal, and
the reviewer's verdict as a quoted block — this is naturally multi-line, so it
exercises the block-write path end to end. README's example ticket was updated
to show `context:` as a block literal and dropped its now-stale `## Description`
heading.

## Real-Command Proof (not only unit tests)

Built a binary from the commit before this plan (`68126c5`) and one from this
worktree, ran identical `jaira init && jaira create "t" --goal g --dod d
--context "single line context"` in two scratch repos, and diffed the
resulting ticket files with only `id`/timestamps normalized:

```
BYTE IDENTICAL (modulo id/timestamps)
```

Then, with the "after" binary, created a ticket with a multi-line `--context`:

```
context: |-
  line one

  line three
```

`jaira show <id> --json` reported `"context": "line one\n\nline three"` (not
`"|"`). Collapsing it with `jaira set <id> context="one line now"` produced
`context: one line now` with no orphaned content lines and
`definition-of-done` on the next line untouched; setting it back to a
multi-line value produced a fresh `context: |-` block again.
