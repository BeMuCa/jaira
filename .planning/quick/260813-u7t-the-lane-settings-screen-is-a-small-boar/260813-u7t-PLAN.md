<objective>
The lane settings screen is a list. The user wants the board itself, small: the
project's lanes as columns, navigable, with the selected one movable left and
right, removable, and a `+` column at the far right that opens the catalogue.

Ordering today comes from each lane's `after:` anchor, which cannot express "put
this one third" without rewriting anchors across several files. The user's model,
stated twice and settled: **a position number counting from 1, and moving a lane
shifts the others by one** — `a=1 b=2 c=3` becomes `a=1 c=2 b=3`.

Those numbers live in ONE file in the project, not in each lane. Decided
deliberately: a move then writes one file rather than eight, and a lane adopted
from a teammate arrives without their position to collide with yours.

**This is not `precedence`.** `core/merge` uses `precedence` to decide which lane
wins when two clones moved the same ticket, which is why `blocked` carries a
deliberately low number. Renumbering it would make a merge pull an in-progress
ticket back into Blocked. `precedence` is not touched by anything in this plan.
</objective>

  <action>
Add `core/lane/order.go` holding the project's column order: a plain list of lane
ids, one per line, position given by line number counting from 1. Pick the file
name and say why in a comment; it lives beside the project's lane files.

    LoadOrder(root string) ([]string, error)   — absent file is not an error
    SaveOrder(root string, ids []string) error
    Move(ids []string, id string, delta int) []string  — pure, testable

`Move` is the user's model exactly: moving a lane one step swaps it with its
neighbour, so `[a b c]` moving `c` by -1 gives `[a c b]`. Moving past either end
is a no-op, not an error and not a wrap-around.

Wire it into loading: when an order file exists, it decides the column order, and
`after:` is no longer consulted for the lanes it names. A lane present in the
project but missing from the order file goes after the ones it names, in the
order it loads today — a lane must never vanish because someone hand-edited the
file. An id in the order file with no lane behind it is a warning, not a failure.

Tests: Move in both directions, at both ends, on a single-element list; an absent
order file leaves today's behaviour unchanged; an order file reorders; an unknown
id warns; a lane missing from the file still appears.
