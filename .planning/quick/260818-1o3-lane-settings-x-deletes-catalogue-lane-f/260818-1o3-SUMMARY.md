# Quick Task 260818-1o3: x reaches catalogue lanes too, and every removal asks first — Summary

x on the lane settings screen now deletes not-installed catalogue lane files (not just board lanes), and every x — board or catalogue — opens a yes/no confirmation defaulting to no, so a stray enter never deletes anything again.

## What changed

`internal/tui/lanes.go`:
- New `confirmRemove` type (`id`, `path`, `yes`) and a `confirm *confirmRemove` field on `laneScreen`. `path` empty means board removal; non-empty means a catalogue file delete.
- `key()` gained a confirm-interception block, checked right after the `catalogueOpen` block and before the normal switch: `h`/`left` sets no, `l`/`right` sets yes, `enter` clears `confirm` and executes the stored action if yes, `esc`/`q` clears `confirm` without finishing the screen. All other keys are ignored while a confirmation is open.
- `x` no longer calls `remove()` directly — it now calls `startRemove()`, which:
  - opens a confirmation on an installed (board) lane under the cursor,
  - opens a confirmation naming the file on a not-installed (available) catalogue lane,
  - errors immediately (no confirmation) on an available built-in — it has no file to delete,
  - is a no-op on the `+` column.
- The old `remove()` was split into `removeBoardLane(id)` (the original `lane.Remove` + reload logic, run when a board-lane confirmation resolves yes) and `deleteCatalogueLane(path)` (new: `os.Remove` + reload, run when a catalogue-lane confirmation resolves yes).
- `render()` now shows the yes/no question and the two answers (`no` before `yes`, selected one in `stySelected`, the other in `styMeta`) in place of the normal footer while `confirm != nil`, with its own hint line `←/→ choose · enter confirm · esc cancel`.

`internal/tui/lanes_test.go`:
- Updated `TestLaneScreenXRemovesSelectedLane` to drive the new `x`, `right`, `enter` sequence, and added an assertion in the same test that a bare `x`+`enter` (default no) removes nothing.
- Updated `TestLaneScreenXRefusesWhenTicketPresent` to the same `x`, `right`, `enter` sequence.
- New `TestLaneScreenXDeletesAvailableCatalogueLane`: `x`, `right`, `enter` on an available catalogue lane deletes its file and it disappears from `ls.available` after reload.
- New `TestLaneScreenXOnAvailableDefaultNoLeavesFileOnDisk`: bare `x`+`enter` on an available lane leaves the file on disk.
- New `TestLaneScreenXOnAvailableBuiltinRefusesWithoutConfirmation`: `x` on an available built-in (reached by first removing it from the board) shows the "nothing to delete" error and opens no confirmation.
- New `TestLaneScreenConfirmEscCancelsWithoutFinishing`: `esc` while confirming clears `confirm`, does not finish the screen (`key` returns false), removes nothing, and the render before `esc` shows `no` before `yes`.

## Deviations from Plan

This was implied by the plan's own reference to that test's setup shape, not a deviation from what was asked.
