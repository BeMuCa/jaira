# Quick Task: jaira works out a ticket's commits itself, syncs it off the board, and stops overwriting your own rules

GitHub issue #4 (BeMuCa/jaira). Three changes, all decided. Decision ids below
are used for traceability: **D-01** derivation, **D-02** `jaira sync`, **D-03**
the local area, **D-04** the note and doc text that has to match.

## What is there today, verbatim

**The commits requirement (D-01).** `core/gate/gate.go:271-279` refuses a move
into any lane declaring `requires-commits` when `len(t.Commits) == 0`, telling
the caller to run `jaira set <id> commits=<sha>` or pass `--commits`. Nothing
derives anything. `core/gate`'s package doc (`gate.go:1-9`) states why it is
pure functions over already-loaded state: unit-testable without a filesystem,
and one file to change when a rule changes. `Env` today is
`{Lanes *lane.Set; All []*ticket.Ticket}` and `core/gate/plan_test.go:11-18`
builds it as `Env{Lanes: lanes}` — a zero value must keep working.

`core/gitrepo/git.go` already shells out through one private `run(args...)`
helper that returns `ErrNoGit` when git is absent, and its public methods
(`Commits`, `Diff`, `Stat`) all swallow per-commit git failures rather than
propagating them. There is no `core/gitrepo/*_test.go` yet.

**Leaving the board (D-02).** `core/ticket/store.go:108-158` has
`ArchiveSubdir`, `ArchiveDir()`, `Archive(id)` (resolve symlink, refuse a name
collision, `os.Rename`) and `Restore(name)` which looks only in `ArchiveDir()`
and reports `"%s is not in the archive"`. `internal/cli/archive.go` is the
shape to mirror: `Args` rejecting more than one id with `ExitUsage`, a no-arg
branch that lists and ends in a hint, and a one-arg branch that moves and
prints where the file went. `Paths()` (`store.go:208-225`) reads only
`TicketsDir()` with `os.ReadDir` and skips directories, so a sibling
`.jaira/sync/` is already invisible to `List()` and therefore to
`core/validate` — this needs a test, not a change.

**The name collision.** `internal/cli/sync.go` holds `newSyncTasksCmd()`
(`jaira sync-tasks`, mirroring an agent task list into the backlog) and
`newTasksCmd()`. Nothing there is related to this work.

**The managed block (D-03).** `core/board/announce.go:94-133` regenerates
everything between `<!-- jaira:start -->` and `<!-- jaira:end -->` wholesale:
`updated := s[:start] + strings.TrimSuffix(block, "\n") + s[end+len(...):]`.
The note itself (`agentNote`, lines 21-66) contains the line this issue is
about: `jaira move ... --commits "$(git rev-parse HEAD)"` — "naming every
commit you made; a ticket cannot be accepted as done without them" — and,
separately, the bullet that the ticket rides in the same commit as the code,
which becomes load-bearing and stays.

## The decisions, restated as they will be built

**Order (D-01).** The recorded list is **oldest-first**, chronological, so the
list reads as the history of the ticket. Stated in a comment on the derivation
and honoured by both callers.

**Union (D-01).** `git log --follow -- <ticket file>` catches every commit the
ticket file rode in; `git log --grep=<full ULID>` catches commits that name the
ticket without touching its file. Neither alone is the answer, so the union is.

**Injection (D-01).** `gate.Env` gains a `DeriveCommits func(*ticket.Ticket)
[]string`. The gate calls it; it never imports `core/gitrepo`. `nil` means "no
derivation on offer" and the refusal stands unchanged, which is what makes
`Env{Lanes: lanes}` in the existing tests keep passing.

**No silent pass (D-01).** The gate only stops refusing when the derivation
came back with at least one sha. An empty result, a git failure, or a `nil`
func all land on today's refusal with today's message.

**Both interfaces (D-01).** The CLI and the TUI both get the derivation. The
gate package doc claims both interfaces enforce identically; wiring only the
CLI would make that false — the same ticket would move from a shell and be
refused in the board.

## Threat notes

Only one input in this work crosses a boundary: the `<file>` argument to
`jaira restore`, which is used to build a path under `.jaira/`. `Restore`
already neutralises traversal with `filepath.Base(name)`; every new path built
from a user-supplied name — the sync-folder search included — must do the same,
and a test asserts it. Nothing here installs a package, opens a socket, or
parses untrusted markup.

End-to-end, by hand, in a throwaway repo (`git init`, `jaira init`): create a
ticket, commit it together with a source change, walk it to the terminal lane
WITHOUT ever passing `--commits`, confirm the terminal lane accepts it, then
`jaira sync <id> --json` and read the stamped list off the moved file. Then
`jaira restore <file>` and confirm it is back on the board.

## Constraints

- Locked decisions only. No alternatives, no flags to turn the derivation off,
  no second way to spell any of this.
- `core/gate` stays filesystem-free and importing no git. The derivation is
  injected or it is not available.
- Never a silent pass: an empty derivation is today's refusal, with today's
  words.
- Explicit beats derived, always. A recorded commit list and a `--commits` on
  the move are untouched.
- `internal/cli/sync.go` is the unrelated `sync-tasks` command. Read it, do not
  edit it, do not let the new command shadow it.
- Repo test conventions: table-driven Go tests next to the code; fixture repos
  built at runtime with `t.TempDir()` and `os/exec`; never a committed nested
  `.git`; `--json` on every read path; exit codes unchanged as a contract.
- Voice: comments explain why a rule exists, in full sentences. Every refusal
  names the command that fixes it.
- No pull request. No push.
