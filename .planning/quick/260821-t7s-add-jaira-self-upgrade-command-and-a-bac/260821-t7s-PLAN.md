- `func downloadBase() string` returning `JAIRA_RELEASE_DOWNLOADS` when set, else

- Comment on both: these exist so the test suite can serve a whole release from
  an `httptest.Server` rather than requiring network access to run `go test`,
  and they incidentally let someone point at a fork. They are deliberately not
  flags, because they are not something a user should be choosing per

Then the client and its operations:

- `type Client struct { HTTP *http.Client }` with `func New() *Client` giving it
  a `*http.Client` with an explicit `Timeout` (30s). Say why in a comment: the
  zero-value `http.Client` has no timeout at all, so a hung TLS handshake would
  hang the command forever, and this command is sometimes run detached where
  nobody would ever see it stuck.
- `type Release struct { Tag, Version string }` — `Tag` carries the leading `v`
  (that is what the download path uses), `Version` does not (that is what
  `release.Current` and the archive name use). Comment the distinction; getting
  it backwards is the obvious bug here.
- `func (c *Client) Latest(ctx context.Context) (Release, error)` — GET
  `apiBase()+"/releases/latest"`, decode only `{"tag_name": "..."}` into a small
  anonymous struct (do not model GitHub's whole payload; the fields we do not
  read are not our contract), derive `Version` by trimming a leading `v`. A
  non-200 is an error naming the status. An empty `tag_name` is an error saying
  no release was found and pointing at `go install github.com/BeMuCa/jaira/cmd/jaira@latest`,
  the same fallback install.sh gives.
- `func AssetName(version, goos, goarch string) string` — `jaira_{version}_{goos}_{goarch}`
  plus `.zip` when `goos == "windows"`, else `.tar.gz`. One comment naming
  .goreleaser.yaml as the thing this must stay in step with.
- `func (c *Client) Binary(ctx context.Context, rel Release, goos, goarch string) ([]byte, error)`
  — the whole verified path, in this order, because the order is the security
  property: download `checksums.txt` first, download the archive, compute
  sha256 over the archive bytes, compare against the line for this asset name,
  and only then extract. Return the extracted binary bytes. Comment that
  nothing is written to disk anywhere in this function: a verification failure
  must not be able to leave a partial file that some other code path could pick
  up.
  - Read both bodies through `io.LimitReader` with a named
    `const maxDownload = 128 << 20` and a comment: an unbounded `io.ReadAll` of
    a remote body is a memory bomb, and no jaira archive is remotely near this.
  - Parse `checksums.txt` with a small helper `func digestFor(checksums []byte, asset string) (string, bool)`
    splitting each line on whitespace into digest and name; treat a missing
    entry as a distinct failure from a mismatched one, and say which in the
    error, because they mean different things to whoever reads it (a broken
    release versus a corrupted or tampered download).
  - Extraction: `func extract(archive []byte, goos string) ([]byte, error)`
    dispatching on `goos` to `archive/tar`+`compress/gzip` or `archive/zip` over
    a `bytes.NewReader`. Take the entry whose `path.Base` is `jaira` or
    `jaira.exe` and ignore any directory prefix, so a future change to
    goreleaser's `wrap_in_directory` does not break this. Error if no such entry,
    or if it is empty.
- `func (c *Client) DownloadURL(tag, asset string) string` — `downloadBase()+"/"+tag+"/"+asset`.

**core/selfupdate/replace.go** (`//go:build !windows`) and
**core/selfupdate/replace_windows.go** (`//go:build windows`)

Both export `func Replace(target string, bin []byte) error` and
`func Sweep(dir string) int`. Put the shared staging in selfupdate.go as
`func stage(target string, bin []byte) (string, error)`: `os.CreateTemp(filepath.Dir(target), ".jaira-upgrade-*")`,
write, `Chmod(0o755)`, `Close`, return the path. Comment why the temp file goes
in the target's own directory and not `os.TempDir()`: a rename across
filesystems is not atomic and on most machines `/tmp` is a different filesystem
from `~/.local/bin`, so the cross-device copy fallback would leave a
half-written binary on a crash.

- Non-windows `Replace`: stage, then `os.Rename(tmp, target)`, removing the temp
  file on any failure. A running process on unix holds its inode, so renaming
  over it is safe and the running process keeps working from the old inode.
  Say that in the comment, because it is the thing a reader will doubt.
- Non-windows `Sweep`: return 0. One comment line: there is nothing to sweep
  because unix never needs to leave the old binary behind.
- Windows `Replace`: `Sweep(filepath.Dir(target))` first, stage, then
  `os.Rename(target, target+".old-"+strconv.Itoa(os.Getpid()))`, then
  `os.Rename(tmp, target)`. If the second rename fails, rename the old file back
  and remove the temp, so a failure leaves the install exactly as it was.
  Comment: Windows refuses to replace the image of a running executable, but it
  will let you rename it out of the way, which is how every self-updating
  Windows tool does this.
- Windows `Sweep`: glob `*.old-*` in the directory, `os.Remove` each, count the
  ones that went. The previous run's binary is no longer running by the time a
  later run starts, so this is where the leftovers actually die. Ignore removal
  errors — a still-locked file simply gets swept next time.

`Path()`: `JAIRA_HOME` else `~/.jaira`, file `update-check.json`. Comment why it
is here and not in `Store.StateDir()`: which release is published is a fact
about the machine, not about a working tree, and putting it per-tree would make
someone with ten clones do ten checks a day for the same answer.

`Write` goes through a temp file in the same directory plus a rename, matching
how the rest of this project writes anything it cares about. `Read` swallows
every error into `(Check{}, false)`, the way `release.Stamped` does — a missing,
truncated or garbage cache is indistinguishable from "never checked" for every
purpose this serves, and a best-effort informational cache must never be able to
fail a command.

`SpawnRefresh`: `os.Executable()`, then
`exec.Command(exe, "self", "upgrade", "--check", "--json")` with all three
stdio handles set to `os.DevNull`, `Env` extended with
`JAIRA_NO_UPDATE_CHECK=1`, then `Start()` and no `Wait()`. Three comments, each
earning its place:

- The env var on the child is a recursion guard: the child must never itself
  decide the cache is stale and spawn a grandchild. It also happens to be the
  same switch a user flips, so there is one mechanism, not two.
- No `Wait()` is the whole point. The parent is about to exit; the child is
  reparented to init and reaped there. There is deliberately no attempt to
  `setsid` — that needs per-OS `SysProcAttr` and buys only immunity from a
  Ctrl-C sent to the process group, and losing a best-effort release check to a
  Ctrl-C costs nothing: the cache stays stale and the next command retries.
- Stdio to `os.DevNull` rather than inherited, because a child writing to the
  parent's terminal after the parent has exited is the exact failure this whole
  design exists to avoid.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| github.com → jaira process | Release metadata, `checksums.txt`, and an archive containing an executable cross into the process from the network. This is the highest-value boundary in the entire project: what crosses it becomes the binary the user runs next. |
| jaira process → the filesystem at `$target` | The process replaces the executable on the user's `PATH`. |
| parent jaira → detached child jaira | A process is spawned with an inherited environment and no supervision. |
| cache file → nudge logic | A file under `~/.jaira` is read on every board command and its contents are rendered to the terminal. |
