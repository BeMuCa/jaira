- Jeder Schreibweg prueft, ob die Datei hinter ihrem Ref liegt, und lehnt dann ab: Store.Mutate core/ticket/store.go:1462, Archive :312, Logbook :456; move prueft zusaetzlich vor dem Gate core/move/move.go:96.

- Die Ablehnung (StaleError, refsync.go:1171) sagt immer 'run jaira pull <id> ... then run this again' - auch wenn pull danach selbst ablehnt (ungesendeter Schreibvorgang, refsync.go:1298).
- Das Nachholen gibt es schon: Syncer.refresh refsync.go:1284. Es fetcht (:1286), vergleicht, lehnt bei ungesendetem Schreibvorgang ab (:1298), schreibt sonst die Bytes des Refs ueber die Datei (:1303), bei geaendertem Titel unter neuem Dateinamen (:1302, alte Datei weg :1308).
- Nur jaira pull ruft refresh (internal/cli/pull.go:55 -> refsync.go:1353). Kein Schreibbefehl tut es. Das ist die ganze Luecke: Pruefen und Nachholen sind getrennt, und dazwischen muss jemand eine Runde drehen.
- jaira fetch nimmt kein Argument (Args: noArgs(), internal/cli/fetch.go:63). Heute ausprobiert: 'jaira fetch 1K3RA8' -> 'fetch takes no arguments, received 1' plus Usage-Zeile, exit 2, kein Wort zu pull.
