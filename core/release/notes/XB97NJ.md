- Working alone without pull requests? Commit a one-line `.jaira/pr` saying `none` (on a board not shared yet, `jaira share` first) and run `jaira update`: the roles then land a branch on the default branch with a fast-forward push once every ticket on it is in done, instead of stopping at a pull request nobody opens. Without the file nothing changes.
- A `.jaira/pr` (or `pr-when`, `release`) saved with a byte order mark now reads as what it says; when `.jaira/pr` holds a word that is neither `agent` nor `none`, `jaira roles list` names that word instead of claiming the default.
- On a board without pull requests (`.jaira/pr` says `none`), write a revert as `fix(<ID>): revert <what>`: `jaira roles pr-gate` refuses git's own `Revert "..."` subject like any commit that names no ticket, and says which form to use.
- On a board whose `.jaira/pr` says `none`, Accept in the cockpit now lands the branch (it says "landing") instead of opening a pull request; a host that is neither GitHub nor GitLab lands on origin without `git config jaira.forge`, and where nothing can land — no origin, a forge that does not answer — the pane says why.
- `jaira roles pr-gate --land <remote>/<branch>` exits 0 only where the base branch itself says `none`; a role lands only behind it, so a branch that commits `.jaira/pr` saying `none` never lands on a board whose base takes pull requests.
- `jaira roles list` now reads `.jaira/pr`, `.jaira/pr-when` and `.jaira/pr-reviewer` as origin's default branch holds them (or `--base <ref>`, which exits 3 `no_such_ref` when the ref is not here), not off your checkout; `pr_source` says when your branch changes `.jaira/pr` since it was cut, and without any base it says the disk was read.
- `jaira roles pr-gate <base>` now refuses a base whose `.jaira/pr` says `none` (reason `no_pull_requests`): land there with `jaira roles pr-gate --land <base>` instead.
