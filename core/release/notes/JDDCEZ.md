- A repository with `.jaira/worktree-setup` can add an executable `.jaira/worktree-teardown`: `reap.sh` calls it with the same four arguments the setup got (worktree, slug, port offset, repo root) after closing a merged ticket's tabs and before removing its worktree — stop the ticket's container stack and delete its volumes there, and make it safe to run twice.
- `spawn.sh` now records the setup's arguments in the worktree's git directory (`jaira-setup`); worktrees spawned before this release have no record, so `reap.sh` calls no teardown for them — take their stacks down by hand.
- `reap.sh` keeps a ticket whose teardown fails (`kept <ticket>: teardown failed: ...`) or is not executable, and tries the teardown again next round.
- `reap.sh` stops a `.jaira/worktree-teardown` that runs longer than `JAIRA_TEARDOWN_TIMEOUT` seconds (default 300) together with its child processes and keeps the ticket as failed; where a teardown is due, a machine without a `timeout`/`gtimeout` that takes `-k` (coreutils — Windows' own `timeout.exe` does not) keeps the ticket.
- ! In `.jaira/worktree-teardown`, use absolute paths or `cd "$1"`: it is always the main checkout's script, and its worktree (`$1`) and repo root (`$4`) are the paths the setup got, which may no longer exist — never rely on `$4`.
