- The review lane no longer receives the implementer's outcome and now hunts for defects in every module its diff touches, copied or moved code included; run `jaira update --lanes` to bring the review lane on your board up to date.
- The testing lane's third pass now triggers at least one failure path and, where the change writes, two parallel writers; run `jaira update --lanes` to get it.
- New role `jaira-role-bughunt`: a fresh agent reads whole modules for concurrency, error-path, input and permission defects and leaves each verified finding as a note; run `jaira update --roles` to install it, and the worker and dispatcher run it before a code-changing ticket goes to review.
- Expect the `diff` that `jaira show <id> --for-lane <lane>` hands a lane to leave out ticket files — `.jaira/tickets/`, `.jaira/logbook/` and `.jaira/archive/` — for committed work and the worktree alike: a lane reads the ticket from its own fields, and the review lane, which no longer takes the outcome, no longer finds it in the ticket file committed beside the code.
- Expect a value in a ticket's `commits:` field that is not a commit id (4 to 64 hex digits) to be shown as not available instead of being passed to git: an entry such as `--output=<path>` used to make `jaira show --for-lane`, the ticket detail pane and the sign-off screen overwrite that file.
- Expect `jaira show <id> --for-lane <lane>` to hand a lane every item of the Definition of Done checklist, numbered with its state, instead of only the first criterion stored in the frontmatter; proofs stay out of the lane input.
