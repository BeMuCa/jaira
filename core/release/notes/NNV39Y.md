- A new private board is now excluded in `.git/info/exclude` instead of `.gitignore`: `jaira init` no longer leaves a modified `.gitignore` in the repository or in any of its worktrees.
- ! Run `jaira update` once on a private board an older jaira set up: it moves the `/.jaira/` line from `.gitignore` to `.git/info/exclude`; commit the changed `.gitignore` so teammates' worktrees stay clean too, and have each teammate run `jaira update` after pulling it so their own private board stays excluded.
- `jaira share` lifts the exclude in `.git/info/exclude` (and an old `.gitignore` line) and still keeps `/.jaira/lanes/` in `.gitignore`; `jaira share --undo` excludes the board in `.git/info/exclude` again.
- `jaira share` removes only the entries jaira wrote; when a rule of yours still ignores `.jaira/` (such as an unanchored `.jaira/` in `.git/info/exclude`, which covers every board in the repository), it names that rule in a warning and reports `still_ignored` in `--json` — remove the rule yourself. Where git cannot answer (a symlinked `.jaira`), `still_ignored` is `null` and `ignore_unknown` says why.
- After `jaira share --undo` and its commit, have each teammate who keeps the board run `jaira update` once: the exclude entry is per clone, and `share --undo` now says so.
- `jaira update` asks git (`git check-ignore`) whether the private board is already ignored, by any rule, and `--json` reports `ignore_moved`, `ignore_added` and `ignore_unknown`; where git cannot answer (a symlinked `.jaira`) it touches nothing and says why. On git older than 2.31 `.gitignore` stays the place: a line there stays, a missing one is written there.
- When `.git/info/exclude` or `.gitignore` exists but cannot be read (for example its permissions), jaira no longer replaces it with only its own entry: `jaira share`, `share --undo` and `update` stop with the read error and `share` leaves the board private, `jaira init` warns and leaves the board unexcluded; fix the file's permissions and run the command again.
