- Set what counts as a blocker on one ticket with `jaira set <id> blocker-rule="<one sentence>"`; testing, review and the bug hunt read it from `jaira show <id> --json` and `--for-lane` as `blocker_rule`, which falls back to a wrong result, data loss, a crash or a security hole when the ticket sets none.
- Set `jaira set <id> stop-after-fix=true` on a ticket where a round after a fix should run the tests only and start no new bug hunt; it is off by default, and `jaira set` refuses any value but true, false or empty.
- Read who sent a ticket back from `back` in `jaira show <id> --json` and in the `--for-lane` payload: `from` is the lane, `by` is `person` (a person's lane, any move made in the board, or `jaira move` typed at a terminal) or `lane`, `count` is the returns in a row from that lane; `jaira move` writes it into the new `back-from`, `back-by` and `back-count` frontmatter fields on every send-back.
- Expect the in-progress lane to stop after the third return in a row from the same lane by reading `back.count`; a person's return never counts, and you no longer need to write a `Given back from <lane>:` note for jaira to tell your return from a loop lane's.
- A value with Windows line endings (CRLF) passed to `jaira set` or `jaira create` is now stored with plain line breaks instead of failing with "value position is at end of line".
- Expect the cockpit to offer Explain only when the review wrote a `blocker:` line (also as `- blocker:`, `Blocker:` or in markdown emphasis such as `**blocker:**`) or the verdict names a reservation; the review's other notes are listed under the ticket's row, without a button.
- Expect a ticket whose review verdict is from an earlier round to say 'review of round N, changed since' in the cockpit and keep its Explain, instead of showing nothing.
- Expect the cockpit's Explain to write a status line (DoD, tests, blockers, bughunt on HEAD, each ok or fail), one line per review note marked [blocker], [small edge], [known limit] or [not this ticket], and one recommendation that says plainly when the ticket can be accepted as it is; options no longer come in a fixed give-back-first order.
- Expect the explanation pane to draw a green tick or a red cross per check, colour only the class marks (blocker red, small edge yellow, known limit dim, not this ticket blue) and show the recommendation bold; explanations written before keep reading as they did.
- Read the review's own findings for a verdict a later round left standing from `review.verdict_gaps` in `jaira show <id> --json` (frontmatter `review-verdict-gaps`); jaira copies review-gaps there whenever the verdict or the gaps are written in the verdict's round, and the cockpit lists those notes under the row instead of nothing.
- Read whether the newest bug hunt still covers the code from `bughunt` in `jaira show <id> --brief`: `at` is its commit, `on_head` is true while no commit naming the ticket since then and no file written after the hunt and not committed touched the files it read (merges, other tickets' commits, uncommitted edits from before the hunt and board data under `.jaira/` other than the lane prompts do not count; a checkout that does not contain the hunt's commit reads false), and `skipped` is true when the ticket sets stop-after-fix and the hunt does not cover HEAD - Explain then writes `bughunt on HEAD skipped`, drawn without a cross, and `null` means no hunt finished - on a stop-after-fix ticket without one it is `skipped` with an empty `at` instead; the cockpit's Explain status line takes `bughunt on HEAD` from it instead of from the four newest notes.
- `stop-after-fix` written by hand as `True` or with spaces is now read as on, the way `jaira set` stores it.
- Expect Explain in the cockpit to be offered for a review verdict of an earlier round only when that review's own findings were kept (`review.verdict_gaps`) or the verdict reserves or refuses; a later lane's lines in `review-gaps` no longer count as the review's blocker.
