- ! Milestones now live on their refs (`refs/jaira/milestones/<ID>`) only: stop committing anything under `.jaira/milestones/` — the next milestone command or `jaira fetch` takes every file there onto its ref, deletes it and says so on stderr; read one by hand with `git show refs/jaira/milestones/<ID>:<name>-<ID>.md`.
- ! A milestone file left under `.jaira/milestones/` that its ref never saw is merged into the ref, not dropped; a stale copy of an older state is deleted without overwriting the ref. A file whose milestone this clone cannot tell from an unfetched teammate's waits until `jaira fetch` reaches the remote (`jaira fetch --json`: `milestones_waiting`).
- On a board without a remote, milestones keep working: they live on local refs and go out with the first send once you configure a remote. A board outside git has no milestones.
- `jaira logbook <milestone>` now only marks its ref `status: filed` and writes no file; bring it back with `jaira restore <name>-<ID>` (its name or ID works too). `jaira logbook` lists filed milestones beside logged tickets (`--json`: `milestones_filed`).
- Milestone `--json` now carries `ref`, and `file` is the file name inside the ref instead of a path; `jaira milestone ls --json` has `refs` instead of `dir`, and messages name the ref where they named a file.
- ! A 0.4.x build that still writes to an old name-keyed milestone ref is no longer heard once the milestone has its ID ref: update every clone to at least 0.5.0.
