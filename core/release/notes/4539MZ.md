- `jaira reject <id> --why ... --force` (and `R` on the board) now rejects a ticket that lives only on its ref: no `jaira pull` first, no archive file in your branch — the rejection is written to the ref and leaves every board after the next fetch.
- ! `jaira reject` exits 3 with `already_rejected` or `filed_away` for a ticket that is no longer on the board, and 5 for an id nothing knows; check those codes where a script read exit 1.
- `jaira pull <id>` on a ticket rejected on its ref, with no file for it here, brings it back and takes the rejection off, saying so in its output and in a note; use it where `jaira restore` finds no archive file.
- `jaira pull <handle>` now finds a ticket created in another clone since your last fetch, without a `jaira fetch` first.
- A rejection on the ref takes the assignee off, and a ticket carrying `rejected-kind` leaves `jaira list` and the board even where its file is in your checkout; `jaira show <id>` still finds it, and deleting that file and running `jaira pull <id>` brings it back.
- `jaira claim` refuses (exit 3, `rejected`) a ticket that carries a rejection; delete its file and `jaira pull <id>` to work it after all, or only `jaira pull <id>` where it was rejected on its ref and has no file here.
- `jaira links`, `jaira show` and the board's link and milestone views name a ticket rejected on its ref as `rejected · off the board` (place `rejected` in `--json`) instead of advising `jaira pull`, which would take the rejection off.
