- Get the jaira-cockpit mod for the Claude Code session you work from by running `jaira roles install --force` (add `--global` to have it in every project; with `--project` Claude Code loads it once you trust the workspace) and starting a new session: agent reports arrive as one line (`/cockpit report <id>` shows them whole), the band above the prompt, framed and titled `jaira-cockpit`, lists tickets waiting for you with Accept / Give back / Explain / Discuss (Give back asks what is missing in a pane of its own, a failed button opens its error whole in a pane, and once the Explain chat has noted its explanation on the ticket the band offers Read explanation and closes the chat's tab, as it closes a Discuss tab once the question is answered), shows context size and prompt-cache time left, holds a prompt of yours onto a cold cache with a large context, files your turns into conversation threads (`/cockpit threads`), `/cockpit ticket <id>` opens a pane, and each session adds a row to `~/.jaira/metrics.csv`; the status line counts the workers and reviews at work (Herdr tabs or this session's subagents) and shows the five-hour and seven-day windows used, every text is in English whatever Claude Code's `language` setting, and in a session that carries a ticket (a worker, lane or dispatcher spawn.sh starts) the mod only writes its record and metrics, so messages to it arrive as written. Without jaira, `/plugin install jaira-cockpit --marketplace BeMuCa/jaira` installs the same mod.
- Tell a person's lane from an agent's in `jaira lanes --json` by the new `human_exit` field (true for `signoff` and `human` on the shipped board, also in `jaira lanes show --json`), and open a chat about a ticket with `spawn.sh --no-worktree <slug> <id> explain` (a review finding explained in plain words and noted back on the ticket as `explain: ...`) or `... discuss` (the ticket's open question talked through and noted back) — run `jaira roles install --force` (add `--global` if you installed them globally) to get the new `spawn.sh`.
