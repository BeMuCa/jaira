Run `jaira update --lanes --roles`: the testing lane then starts the bug hunt itself, beside its tests, and owes `hunt-verdict` as well as `test-verdict` — a ticket is refused leaving testing until both are set. Until your board's testing lane is updated, the updated worker and dispatcher keep starting the hunt themselves before review, as before; a board without a testing lane keeps it that way.
- Expect each `bughunt:` note to be marked `change` or `pre-existing`: only a `change` finding sends a ticket back to in-progress; a `pre-existing` one becomes a note for the person who accepts the ticket, or a ticket of its own that follows it.
- Expect a second bug hunt on the same ticket to read only what changed since the first one's `done at` commit, plus any file new to the change; the closing `bughunt: done at` line now lists the files it read after `files:`.
- Expect `jaira update --lanes --dry-run` to name only the agent instruction files the real run would change: it used to preview them from the lanes still on disk, before the refresh, and could name a file the real run then left alone.
