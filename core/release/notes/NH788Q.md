- After upgrading jaira you no longer run 'jaira update --lanes' in every repository: the first jaira command in a repository brings every lane nobody edited, and the jaira section in CLAUDE.md/AGENTS.md where it already stands, up to the new version and says so in one line on stderr. Review and commit those files like any other change; a lane you edited is left alone and named in that line. Run 'jaira update' as before to read what changed in the release.
- Expect 'jaira update --lanes' and the automatic refresh to bring the lanes of named boards (.jaira/boards/<name>/lanes) up to date too; a command run with --dry-run leaves the refresh to the next command.
- Replace an edited lane of a named board by hand: 'jaira update --lanes' names it without offering 'jaira lanes use', which writes today's board only, and its --json result carries a "board" key for such a lane.
- Expect the jaira section in CLAUDE.md/AGENTS.md to open with '<!-- jaira:version X.Y.Z -->', the version that last changed its text; an older jaira's automatic refresh leaves such a section alone instead of writing its own older text back, so teammates on two versions no longer rewrite it back and forth.
- Expect the automatic lane refresh and every other jaira write on Windows to wait a moment for a file another program is reading instead of failing with "Access is denied".
